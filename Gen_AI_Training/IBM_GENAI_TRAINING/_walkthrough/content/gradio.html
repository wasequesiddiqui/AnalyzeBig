In one breath

Two short files that turn a Python function into a web page. qbot.py is a working RAG chatbot: upload a PDF, it is chunked and embedded into Chroma, and your question is answered from the PDF's own text. common_input_types.py is the component reference sheet - slider, dropdown, checkbox group, radio, multi-select, checkbox - with no model calls at all.

Why GradioYou write a normal Python function and Gradio generates the HTML, CSS, JavaScript and web server. No routes, no templates, no fetch code - the whole UI is a declarative list of components.
One number ruins the chatbotTRUNCATE_INPUT_TOKENS: 3 cuts every chunk to three tokens before embedding. The pipeline runs, the UI looks fine, and the answers are poor - because the vectors describe almost nothing. Fix it to 512 and compare.

Think of a photocopy shop with a smart assistant

You hand over a thick booklet (the PDF). The shop assistant does not memorise it - they break it into stapled pages (chunks), write a one-line index card for every page (embeddings), and file the cards in a drawer (Chroma). When you ask a question, they pull the few most relevant pages and read them before answering.

  • Stapling = RecursiveCharacterTextSplitter.
  • Index cards = the embedding model, i.e. numbers describing meaning.
  • Drawer = the Chroma vector store.
  • Counter window = the Gradio interface, where you hand over the booklet and ask.

Before you run it

cd Gradio
pip install gradio langchain-ibm ibm-watsonx-ai \
  langchain-community pypdf python-dotenv
python qbot.py
# open http://localhost:7860

Try this

  • Upload any 5-10 page PDF and ask about its contents.
  • Ask something not in the PDF and watch the model invent an answer - the chain has no "I don't know" instruction.
  • Run common_input_types.py to play with every widget.
