Reflection Agent

An AI system that drafts, critiques, and iteratively refines LinkedIn posts using LangGraph's StateGraph and DeepSeek.

LangGraph · StateGraph · DeepSeek · Python

1. What is a Reflection Agent?

A Reflection Agent is an AI system that can evaluate its own outputs, identify weaknesses, and iteratively improve through feedback loops. It mirrors how humans refine their work: draft → review → revise.

System 1 vs System 2

Borrowing from Daniel Kahneman's framework:

  • System 1 (Generation) — Quick, instinctive first draft. High temperature (0.7) for creativity.
  • System 2 (Reflection) — Deliberate critique and refinement. Low temperature (0.2) for consistency.

The agent cycles between these two modes until quality standards are met or a maximum iteration limit is reached.

2. Workflow

START │ ▼ GENERATE (System 1 — creative draft) │ ▼ REFLECT (System 2 — critique + score) │ ▼ EVALUATE SCORE ├── score ≥ 8.5/10 ──→ END (quality met) └── score < 8.5 ────→ GENERATE AGAIN └── max 4 iterations ──→ END (safety limit)

Step by Step

  1. Generate — The LLM produces an initial LinkedIn post based on the user prompt.
  2. Reflect — A second LLM call (with lower temperature) critiques the post and assigns a quality score.
  3. Route — The router checks the score. If ≥ 8.5 the workflow ends. Otherwise it loops back to generation.
  4. Iterate — The generation node revises the post incorporating the critique. Repeat until threshold or max 4 iterations.
  5. Output — The final post is displayed and saved to final_linkedin_post.md.

3. State Management (AgentState)

The workflow uses LangGraph's StateGraph with an explicit typed state defined via TypedDict.

Field Type Description
messages Annotated[List[BaseMessage], add_messages] Conversation history. Each node appends rather than overwrites, preserving full context across cycles.
iteration int Zero-based count of completed generate–reflect cycles. Incremented by the reflection node.
quality_score float Numeric score (0.0–10.0) extracted from the latest reflection critique.
latest_feedback str Raw text of the most recent critique. Useful for external logging or inspection.
final_post str The latest generated post. At workflow end this holds the best (or last) version.

The add_messages reducer ensures that state updates from each node are appended rather than overwritten, so the message list grows naturally throughout the workflow.

4. Prompts

Two separate prompts drive the two nodes. Both use ChatPromptTemplate from LangChain with a MessagesPlaceholder for the conversation history.

Generation Prompt (System 1)

You are an elite LinkedIn content strategist.

Your ONLY task is to generate a high-performing
LinkedIn post.

Rules:
- Output ONLY the post
- No explanations
- No markdown fences
- No commentary
- Optimize for engagement
- Maintain professional tone
- Include a strong hook
- Include emotional resonance
- Add CTA if appropriate

Reflection Prompt (System 2)

You are a senior LinkedIn growth strategist.

Critique the LinkedIn post.

Return:
1. Quality score from 1-10
2. Weaknesses
3. Specific improvements

Be brutally honest.

Key design choices:

  • The generation prompt explicitly bans meta-commentary ("Output ONLY the post") to prevent conversational responses.
  • The reflection prompt requests a N/10 score, which is extracted by a regex helper function.
  • Separate LLM instances with different temperatures allow creative generation (0.7) and focused critique (0.2).

5. Scoring & Routing

Score Extraction

The extract_score() helper uses a regex to find patterns like 7/10 or 8.5/10 in the reflection output:

import re
match = re.search(r'(\d+(\.\d+)?)\s*/?\s*10', text)
if match:
    return float(match.group(1))
return 5.0  # neutral default

If no score pattern is found, a default of 5.0 is returned so the workflow continues rather than prematurely stopping.

Router Logic

The router() function is the conditional edge attached to the "reflect" node. It checks two stopping criteria:

  1. Quality threshold: If score ≥ MIN_QUALITY_SCORE (8.5) → route to END.
  2. Max iterations: If iteration ≥ MAX_ITERATIONS (4) → route to END (safety limit).
  3. Otherwise: Route back to "generate" for another refinement cycle.

6. Configuration

All tunable parameters live in the Config class for easy experimentation:

Parameter Value Purpose
MODEL_NAME deepseek-chat DeepSeek model identifier used for all LLM calls.
BASE_URL https://api.deepseek.com/v1 DeepSeek's OpenAI-compatible API endpoint.
MAX_ITERATIONS 4 Maximum generate–reflect cycles before forced exit. Prevents infinite loops.
MIN_QUALITY_SCORE 8.5 Score threshold for early stopping. When score ≥ this → END.
TEMPERATURE_GENERATE 0.7 Higher = more creative, varied drafts (System 1).
TEMPERATURE_REFLECT 0.2 Lower = more focused, consistent critiques (System 2).
TIMEOUT_SECONDS 120 Max wall-clock time for the full workflow. Prevents indefinite hangs.

8. Why is the Critique Wrapped in HumanMessage?

The reflection node returns its critique as a HumanMessage rather than AIMessage. This is deliberate:

  • The generation prompt uses a MessagesPlaceholder that expects user messages to trigger revision.
  • By wrapping the critique as a HumanMessage, the generation node treats it as user feedback and revises the post accordingly.
  • This creates a natural loop: AI generates → AI critiques (masquerading as user) → AI revises.

9. Error Handling & Fallbacks

  • Missing API key: Raises ValueError with clear instructions.
  • API failure / timeout: Caught by the try/except in main(). A hardcoded fallback post is printed instead.
  • Graphviz not installed: export_graph() catches the exception silently and falls back to Mermaid text format.

10. Output

When the workflow completes successfully, it produces:

  • advanced_reflection_graph.png or .mmd: A visualisation of the workflow graph.
  • Logs: Timestamped INFO-level logs showing each step and score.
