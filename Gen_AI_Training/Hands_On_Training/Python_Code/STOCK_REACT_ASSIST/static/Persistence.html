Chroma Persistence Layer

Every aspect and function in CHROMA_STORE.py

11 functions · 6 sections · 1 collection
◆
This module is a persistence layer, not an agent. It stores an analysis snapshot into a Chroma Cloud collection — there are no investor personas or LLM calls here. Each save creates one document whose text is the full labelled snapshot (so it stays semantically retrievable) alongside scalar metadata for filtering. Every save is a new record, so history is append-only.

The write path

save_analysis_record
record: dict │ ├─ _render_document(record) ──────► document text (labelled markdown, embedded) ├─ _render_metadata(record) ──────► metadata (flat scalars, filterable) └─ _ticker_token(ticker) + now() ─► doc_id ({TOKEN}_{YYYYMMDD_HHMMSS}) │ ▼ get_collection().add(ids=[doc_id], documents=[document], metadatas=[metadata]) │ └─► returns doc_id

Validation happens before any network call: the record must carry a ticker and/or company_name, otherwise ValueError is raised. The three renderers are pure functions over the dict, which is what makes them cheap to test without a live Chroma connection.

Lazy client construction

get_client()
import chromadb # deferred on purpose chromadb.HttpClient( host = os.getenv("CHROMA_HOST", "api.trychroma.com"), port = 8000, ssl = True, headers = {"X-Chroma-Token": _require_env("CHROMA_API_KEY", "Chroma Cloud")}, tenant = os.getenv("CHROMA_TENANT") or "default_tenant", database= os.getenv("CHROMA_DATABASE", "StockAnalytics"), )

import chromadb is deliberately inside the function, mirroring the lazy crewAI import in PERSONA_AGENTS_CREW.py. Importing this module therefore never slows the Streamlit boot. The client is memoised in the module-level _client global, so the connection is built once per process.

Note that port=8000 and ssl=True are hard-coded — only host is configurable.

Authentication

the gotcha that breaks first
# ✅ works with Chroma Cloud headers = {"X-Chroma-Token": api_key} # ❌ rejected -> ChromaError: Permission denied headers = {"Authorization": f"Bearer {api_key}"}

Chroma Cloud authenticates with the API key in the X-Chroma-Token header. A conventional Authorization: Bearer header is rejected with Permission denied, which looks like a bad key rather than a bad header — the single most likely thing to debug here.

The collection is memoised in the module-level _collection global. hnsw:space is fixed at creation time — changing it later has no effect on an existing collection, so it should be treated as permanent.

The embedding function is what makes stored snapshots semantically searchable later. It is only invoked when documents are added or queried — count() and get_recent() do not embed anything, so they work without OPENAI_API_KEY being valid.

Document layout

_render_document(record)
# Stock Analysis Snapshot Ticker: INFY.NS Company: Infosys Generated: 2026-09-19 10:42:07 ## Financial Outlook <commentary> | "No commentary available." ## Key Risks <commentary> | "No commentary available." ## Growth Potential <commentary> | "No commentary available." ## Investment Recommendation Verdict: BUY <commentary> | "No commentary available." ## Overall Technical Summary Technical Verdict: STRONG BUY <summary> | "No technical summary available." ## Persona Lead-Analyst Consensus Market price: 1,502.30 INR Min fair value: ... Avg ... Max ... Blended stance: Undervalued Lead-analyst commentary: ... | "Persona agents were not run for this snapshot."

Sections are joined with a blank line ("\n\n".join(parts)) so the document reads cleanly when retrieved by a similarity search and pasted into a prompt. Every section is always emitted — a missing value produces an explicit fallback sentence rather than a silently shortened document, which keeps the shape of stored records consistent across saves.

Presence logic

has_persona
\[ \text{has\_persona} \;=\; \text{record}[\texttt{"has\_persona"}] \;\lor\; \big(\text{record}[\texttt{"persona"}] \neq \varnothing\big) \]

A non-empty persona dict flips the flag on its own — the caller cannot accidentally store persona data while reporting has_persona = False. It is a one-way override, so the flag is best read as "persona data is present", never as "the caller asserted it".

In the document itself the test is simply if persona: — an empty or missing dict renders "Persona agents were not run for this snapshot."

Implemented by _render_document() and _render_metadata()

Behaviour worth knowing

affects what you can query
BehaviourConsequence
Optional float keys The four persona_* numbers are added only when not None. A record saved without personas therefore has a different metadata schema than one saved with them — so a range filter on persona_max_fair_value silently excludes persona-less records.
saved_at fallback Falls back to datetime.now() when the record has no generated_at. This is the server's local clock, so the value should be treated as a label rather than a trustworthy event time.
Verdicts upper-cased Metadata stores BUY / STRONG BUY regardless of input casing, so filters must match upper-case exactly.
Empty strings kept Missing text becomes "" rather than being omitted, so every record has the full scalar schema for the string keys.
No numeric guard float(value) is applied without a try/except — a non-numeric market_price raises rather than being coerced or dropped.
1

Document id

_ticker_token()
\[ \text{doc\_id} \;=\; \text{ticker\_token} \;+\; \text{"\_"} \;+\; \text{strftime(timestamp)} \]
_ticker_token("INFY.NS") -> "INFYNS" _ticker_token("BRK-B") -> "BRKB" _ticker_token("") -> "UNKNOWN" doc_id -> "INFYNS_20260919_104207"

The token strips every non-alphanumeric character and upper-cases the result, falling back to UNKNOWN when nothing survives. Combined with a second-resolution timestamp this gives a readable, sortable id.

The timestamp is only second-resolution, and the collection uses add() rather than upsert() — so two saves of the same ticker within the same second produce a duplicate id, which Chroma rejects.

2

Writing a snapshot

save_analysis_record()
ticker = _clean_text(record.get("ticker")) company = _clean_text(record.get("company_name")) if not ticker and not company: raise ValueError("save_analysis_record requires a ticker and/or company_name.") document = _render_document(record) metadata = _render_metadata(record) doc_id = f"{_ticker_token(ticker)}_{now:%Y%m%d_%H%M%S}" get_collection().add(ids=[doc_id], documents=[document], metadatas=[metadata]) return doc_id

Validation is the only failure the caller is expected to handle — it happens before any network I/O, so a malformed record never opens a connection. Everything after it can still fail on credentials, quota or network, and those propagate as Chroma/requests exceptions.

History is append-only by design: saving the same ticker twice creates two documents, which is what makes the store a time series of analyses rather than a latest-value cache.

Reading back

count() · get_recent()
count() # -> int, total snapshots in the collection get_recent(limit=5) get_collection().get(limit=limit, include=["documents", "metadatas"]) -> list(zip(ids, documents, metadatas)) -> [(id, document, metadata), ...]

count() is a cheap collection-level call and does not embed anything. get_recent() returns triples with all three lists zipped positionally.

!
The name overstates the guarantee. Chroma's get() has no sort parameter, so records come back in storage order — not sorted by saved_at. "Recent" is therefore not enforced: if you need true newest-first ordering, sort the returned metadata on the client side.

Notable behaviours

read before debugging
LocationBehaviour
get_client() Chroma Cloud requires the API key in an X-Chroma-Token header. A standard Authorization: Bearer header is rejected with Permission denied, which reads like an invalid key rather than a wrong header.
module top level import chromadb is deferred into get_client(), so importing the module costs nothing and the Streamlit boot is unaffected — mirroring the lazy crewAI import.
_render_metadata() The four persona_* float keys are omitted when None, so persona-less records have a different metadata schema. Range filters on those keys silently skip them.
_render_metadata() Chroma metadata is scalar-only (str/int/float/bool), which is why the nested persona dict has to be flattened into prefixed keys.
doc_id Second-resolution timestamp plus add() (not upsert()) means two saves of the same ticker inside one second collide and raise.
get_recent() Chroma's get() takes no sort parameter, so there is no ordering guarantee despite the name — sort client-side if newest-first matters.
_render_document() Every section is always emitted with an explicit fallback sentence, so stored documents keep a consistent shape even when parts of the analysis are missing.
_fmt_value() Formats to exactly 2 decimal places and appends the currency as a suffix: "1,502.30 INR". It returns "" for None, which callers test for truthiness before emitting a line.
Global caches _client and _collection are module-level singletons with no invalidation hook — credentials are effectively fixed for the process lifetime.
_client / _collection Both are plain globals, not thread-local. Under Streamlit's threaded model this is safe because assignment is atomic and the worst case is building the collection twice.
get_collection() hnsw:space = "cosine" is fixed at collection creation — changing it later has no effect on an existing collection.
save_analysis_record() Performs no aggregation or validation of persona numbers; it renders whatever dict it is handed. The only numeric coercion is float(...) in _render_metadata, which raises on a non-numeric value.
