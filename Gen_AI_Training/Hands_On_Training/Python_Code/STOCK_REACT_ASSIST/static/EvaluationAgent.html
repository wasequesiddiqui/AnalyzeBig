This module follows a ReAct (Reasoning + Acting) pattern. It contains two LLM personas — a fundamental analyst and a quantitative technical analyst — which run in parallel on separate threads. The numbers they reason about come from three deterministic @tool functions, never from the model. A rule-based matrix then merges both verdicts into one Overall Summary.

Fundamental Analyst

Senior Wall Street analyst

Reasons over price, sentiment and news to produce four narrative sections plus a BUY / HOLD / SELL recommendation.

Technical Analyst

Expert quantitative analyst

Reads a RAG-retrieved corpus built from the 5-year indicator DataFrame and classifies the stock on a four-flag scale.

Only two personas exist in this module. They are deliberately complementary rather than a panel: one is qualitative (narrative + news), the other is quantitative (indicators). The multi-persona investor model lives in PERSONA_BASED_VALUATION.py and PERSONA_AGENTS_CREW.py.

Fundamental Analyst

LLM Persona 1 BUY / HOLD / SELL

"You are a senior Wall Street analyst." — narrative-driven, reads the price, the crowd's mood and the headlines, and commits to a rating.

1

Role prompt

verbatim, abridged
You are a senior Wall Street analyst. Analyze this stock. Ticker: {ticker} Stock Data: {stock_data} Sentiment: {sentiment_data} News: {news} Provide a structured analysis with EXACTLY these four sections. Use the exact section headers below (with the emoji), and format each as flowing paragraphs:

All three data payloads are interpolated directly into the prompt — this persona does not use retrieval. The dicts and lists are stringified with their Python repr, so the LLM sees the raw tool output.

2

Required output contract

4 sections, fixed headers
SectionContent demanded by the prompt
## 📊 Financial Outlook2–3 paragraphs on current financial performance and the short-term outlook.
## ⚠️ Key Risks2–3 paragraphs on the major risks investors should be aware of.
## 🚀 Growth Potential2–3 paragraphs on upside opportunities and catalysts.
## 🎯 Investment RecommendationVerdict word in bold as the very first characters — exactly one of **BUY.** / **HOLD.** / **SELL.** — then 1–2 paragraphs of reasoning. In this section only, the single most critical sentence of each paragraph is wrapped in <mark> tags.
3

Prompt engineering rules

explicitly encoded in the prompt
RULE 01

Role instruction

Sets tone, register and expected analytical depth.

RULE 02

Exactly four sections

Fixed headers guarantee the downstream markdown parser can extract each section reliably.

RULE 03

<mark> quarantine

Allowed in the Recommendation section only, so intentional HTML cannot leak into sections that are rendered as escaped text.

RULE 04

No preamble

The first characters must be the first header, otherwise the section splitter mis-assigns content.

Implemented by generate_analysis() → returns raw markdown string llm.invoke(prompt) bounded by ThreadPoolExecutor

Technical Analyst

LLM Persona 2 4-flag verdict RAG-grounded

"You are an expert quantitative analyst specialising in technical analysis." — reads only the retrieved indicator documents and refuses to invent numbers.

1

Role prompt

verbatim, abridged
You are an expert quantitative analyst specialising in technical analysis. Analyse the technical indicators below for the stock {ticker} using ONLY the retrieved documents provided. These documents were retrieved via retrieval-augmented generation (RAG) from a 5-year daily technical-indicator database. Retrieved Documents (RAG): {rag_context} Rules: - Base every statement strictly on the numbers provided; never invent values. - Do not add any preamble before the first section header. - Keep every indicator analysis to 1-2 sentences. - Use only the four verdict flags above.
2

The RAG pipeline

no embeddings, no vector DB
\[ \text{score}(d \mid q) \;=\; \sum_{t \in q} \Big[\, 3.0\cdot\mathbb{1}[t \in K_d] \;+\; 1.5\cdot\mathbb{1}[t \in T_d] \;+\; 0.2\cdot\min\!\big(\text{count}(t, C_d),\,5\big) \Big] \]

The indicator DataFrame is split into 9 topic documents (overview, price_ma, volume_ma, rsi, macd, bollinger, stochastic, obv, recent_price). Each carries a keyword list, a title and a content body. The retriever scores each document with a dependency-free BM25-style keyword filter — keyword hit 3.0, title hit 1.5, content frequency 0.2 per occurrence capped at 5 — then ranks descending.

ReAct Tools

Acting layer Deterministic

The three @tool-decorated functions the LLM can invoke. They are the only source of ground truth — the personas reason about these numbers but never generate them.

!
Docstrings are prompts. With @tool, each function's docstring becomes the description the LLM sees when deciding whether to call it. Rewording a docstring changes agent behaviour even though the code is untouched.
1

get_stock_price

@tool · yfinance
get_stock_price.invoke(ticker: str) -> dict

Fetches the latest OHLCV bar for the symbol exactly as supplied — no .NS / .BO suffix is ever appended or probed. Requests period="5d" so a weekend gap still yields a bar, then takes iloc[-1].

ReturnsDetail
ticker / exchangeEchoed symbol; exchange derived from the suffix after the fetch.
current_price / open / high / lowLatest bar, rounded to 2 dp.
volumeInteger share count.
errorOn any failure — empty history, network error, unexpected shape — a single-key error dict replaces the payload. Never raises.
Depends on yfinance.Tickerpandas
2

get_stock_news

@tool · NewsAPI
get_stock_news.invoke(company_name: str) -> list

Queries NewsAPI /v2/everything with q = "{company_name} stock", English only, sorted by publishedAt, capped at page_size=5 to protect the context window. Only title, description and url are kept per article.

Takes the full company name, not the ticker — NewsAPI searches prose, not symbols. Returns [] when there is no coverage, and a single error-entry list on exception.

Depends on newsapi (module-level client)NEWS_API_KEY
3

analyze_news_sentiment

@tool · TextBlob
analyze_news_sentiment.invoke(company_name: str) -> dict
\[ \bar{p} \;=\; \frac{1}{n}\sum_{i=1}^{n} \text{Polarity}\big(\text{title}_i \;+\; \text{description}_i\big) \]
\[ \text{sentiment} = \begin{cases} \text{Positive} & \bar{p} > +0.15 \\ \text{Negative} & \bar{p} < -0.15 \\ \text{Neutral} & \text{otherwise}\end{cases} \]

Uses a larger sample than the headlines tool (page_size=20) for a statistically meaningful average. Title and description are concatenated before scoring — more signal than the title alone. TextBlob is lexicon-based, so it is fast and keyless but can miss sarcasm and financial jargon.

Degenerate cases are explicit: no articles → {"sentiment": "Unknown", "score": 0, "reason": ...}; exception → {"sentiment": "Error", ...}.

Depends on newsapiTextBlobNLTK punkt data

Notable behaviours

read before trusting output
LocationBehaviour
generate_technical_analysis() The retrieval query is a long fixed string listing every topic, and k defaults to None — which makes _retrieve_technical_docs() return all 9 documents. So the RAG step re-ranks the corpus but never filters it: the full indicator context always reaches the prompt.
parse_technical_analysis() Indicator values in the report come from tech_df, not the LLM. The model supplies only the prose interpretation, so a hallucinated number can appear in commentary but never in the displayed metric.
parse_technical_analysis() The section splitter uses re.split(r'(?m)^##\s+'). The (?m)^ anchor is essential — a bare ##\s+ would also match the second and third # of every ### indicator header and corrupt the parse.
build_overall_summary() Conflicting signals always resolve to HOLD, never to the stronger side. A bearish fundamental view cannot be overruled by bullish technicals.
generate_analysis() Data is interpolated with an f-string, so the prompt contains the Python repr of the dicts and lists — including a full error dict if a tool failed. The model can therefore read a failure and reason about it.
generate_html_report() Writes {CLEAN_TICKER}_REPORT_{YYYY_MM_DD}.html as a bare relative path, so it lands in the process working directory — the repo root on Streamlit Cloud, not the app folder.
main() Calls webbrowser.open() on the generated report. That is CLI-only behaviour; the Streamlit app calls generate_html_report() directly and never triggers a browser launch.
main() The technical agent is submitted only when tech_df is not None. If indicator computation failed, future_tech stays None and the report renders a "Technical Analysis Unavailable" card rather than hanging on a missing future.
highlight_bull_bear() vs _escaped() Two variants exist on purpose. The _escaped form escapes first, for untrusted LLM text; the plain form assumes the input already contains intentional markup (such as the prompt-mandated <mark> tags).
