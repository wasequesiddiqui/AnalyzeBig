The analysis pipeline

run_analysis — 9 steps, synchronously
  1. Stock priceget_stock_price — OHLCV snapshot. A failure here aborts the run.
  2. Newsget_stock_news — latest headlines for the company name.
  3. Sentimentanalyze_news_sentiment — TextBlob polarity over 20 articles.
  4. DCF valuationget_dcf_valuation — multi-model intrinsic value.
  5. RAG corpus buildPDF extraction + chunking, only when the upload set changed.
  6. Lexical retrievalTop-10 chunks by keyword overlap → prompt context.
  7. Technical indicatorsTECH_ANALYSIS — 5-year DataFrame; a failure sets tech_df = None.
  8. Parallel AI analysisFundamental + technical agents on two threads.
  9. Parse & merge verdictsparse_analysis + build_overall_summary → Overall Summary.

Progress is reported through a st.progress bar and a status line, and each stage writes into st.session_state as it completes. The run ends with st.rerun() so main()'s results branch takes over — which is why an interrupted run still renders whatever completed.

Secrets bridge

_load_secrets_into_env()
load_dotenv() # local .env -> os.environ _load_secrets_into_env() # st.secrets -> os.environ (setdefault) for key, value in st.secrets.items(): if isinstance(value, (str, int, float, bool)): os.environ.setdefault(key, str(value))

On Streamlit Community Cloud there is no .env — keys are entered as app Secrets and exposed only through st.secrets, which does not populate os.environ. Every client in this app reads os.getenv(...), so without this bridge each one would silently get None. setdefault means a real environment variable or a local .env always wins.

st.secrets is a lazy proxy: reading the attribute is safe, but the file is not parsed until .items() is called — and that raises when no secrets.toml exists, which is the normal local case. That is why the whole read sits inside a try and is materialised with list(). Nested TOML sections are skipped because only scalars map to environment variables.

2

NLTK bootstrap

_ensure_nltk_data() · @st.cache_resource
for resource, path in (("punkt_tab", "tokenizers/punkt_tab"), ("punkt", "tokenizers/punkt")): try: nltk.data.find(path) except LookupError: nltk.download(resource, quiet=True) # failures swallowed

A fresh Cloud container ships no NLTK data, and TextBlob tokenizes with word_tokenize, which raises LookupError without punkt. This downloads once per container into ~/nltk_data. Both a missing nltk import and a failed download are swallowed so the app still boots — sentiment degrades rather than the page breaking.

@st.cache_resource (not cache_data) is correct here: this is a side-effecting setup routine that should run once per process, not a pure data fetch.

API key verification

_probe_endpoint() · _verify_api_keys()

The sidebar presence check only proves a variable is set — a leftover placeholder like sk-xxxxxxxx passes it happily. These helpers make one cheap authenticated request per provider so "valid" means the key actually works. Uses only urllib, so it adds nothing to requirements.txt.

Probe resultConditionMeaning
validHTTP 200Key authenticated successfully.
invalidHTTP 401 / 403Provider rejected the key itself — placeholder, typo or expired.
unknownAny other status, or a connection failureCould not verify — a provider outage or blocked network is never mistaken for a bad key.

Endpoints are chosen to be authenticated but free: DeepSeek's /user/balance, and a single-article NewsAPI query. The NewsAPI probe still consumes one request from the free-tier daily quota, which is why this is button-driven and cached for 10 minutes, keyed on the key values so rotating a key re-checks immediately.

Yahoo rate-limit strategy

two defences

Yahoo Finance rate-limits by IP address, and Streamlit Community Cloud apps share heavily used AWS egress IPs — so yfinance can raise YFRateLimitError even on the first call of a session.

DEFENCE 01

Cache every fetch

@st.cache_data(ttl=900) means one successful fetch serves every rerun and every session in the process until the TTL expires.

_cached_dcf_valuation · _cached_stock_price · _cached_technical_indicators
DEFENCE 02

Retry with backoff

Up to 3 attempts with linear backoff (2 s, 4 s), because the limit is often just a burst. A genuine "no such ticker" failure is not retried.

_retry_on_rate_limit
def fetch(): hist = yf.Ticker(symbol).history(period="5d") if hist.empty: raise RuntimeError(...) # RAISE, never return an error value _retry_on_rate_limit(fetch)

Why cached fetchers must raise. st.cache_data stores whatever comes back — caching a transient "Too Many Requests" dict would keep showing that error for the whole TTL, even after Yahoo recovered. Raising also lets _retry_on_rate_limit see the failure and retry it. _raise_if_error enforces this for the two fetchers that delegate to other modules.

_yahoo_error_message rewrites a raw "Too Many Requests" into an actionable explanation, because on shared cloud hosts that message otherwise reads like an app bug.

Prompt construction

Assembles the fundamental prompt from six inputs — ticker, stock data, sentiment, news, DCF data and the retrieved RAG excerpts — plus the display currency, then demands four labelled ## sections ending in a bolded verdict word. The <mark> tags are quarantined to the recommendation section so intentional HTML cannot leak into sections rendered as escaped text.

2

Parsing & verdict detection

parse_analysis() — the trickiest logic here

Splits the markdown on ## headers, matches each against the four known sections, extracts paragraphs, and for the recommendation section only detects a BUY / HOLD / SELL verdict in two stages.

  1. Explicit marker winsA leading **HOLD.**, BUY: or SELL — is returned directly, preventing false positives from words like "avoid" later in the commentary.
  2. Keyword scan with negation awarenessOtherwise the body is scanned for BUY words, then SELL words — where a keyword only counts if no negator sits nearby.
  3. Default to HOLDNothing matched, so the verdict is neutral rather than guessed.
\[ \text{directional}(w) \;\iff\; \exists\, \text{occurrence of } w \text{ with no negator within } 45 \text{ chars} \]

The negation guard is what stops "a SELL rating is not warranted" being read as SELL and "a BUY would be premature" being read as BUY. Two limits make it precise: a 45-character window keeps an unrelated "no" elsewhere in the sentence from suppressing the call, and a clause-break test (comma, semicolon, colon, or a conjunction like and/but/however/although) stops "the company has no debt and we recommend BUY" from reading as negated.

Returned per sectionValue
titleCanonical section name when matched, else the raw header.
emojiPer-section icon; unmatched sections get a generic 📌.
paragraphsBody split on blank lines.
is_recommendationTrue for the Investment Recommendation section only.
verdictBUY / HOLD / SELL for that section, None for the rest.
1

The five stages

no embeddings, no vector database

Vectorless RAG keeps the retrieval + augmented generation idea but drops the embedding and vector-database machinery entirely. The chunk list held in st.session_state is the database, and the LLM's long context window does the semantic reading.

  1. EXTRACTextract_pdf_text — raw text per page via pypdf.
  2. CHUNKchunk_text — ~1800-char chunks with 200-char overlap, cut at sentence boundaries.
  3. STOREA plain Python list in session state. No index, no embedding model, no external service.
  4. RETRIEVElexical_search — count query terms present in each chunk, keep the top 10.
  5. AUGMENTformat_rag_context — label each excerpt with file and page, then inject as plain text.
2

Retrieval scoring

lexical_search()
\[ \text{score}(c) \;=\; \bigl|\{\, t \in Q \;:\; t \subseteq \text{lower}(c.\text{text}) \,\}\bigr| \]

A case-insensitive substring overlap count — the stand-in for embedding similarity search. Query terms are extracted with [a-zA-Z]{3,} and filtered against a stop-word set that includes domain words like stock, report, filing and regulatory so they don't dominate the score. Chunks scoring zero are dropped; an empty or too-short query falls back to the first top_k chunks rather than returning nothing.

ADVANTAGE

Zero infrastructure

No embedding model to download or call, no vector database to run, and no embedding cost — only the DeepSeek context window is consumed.

ADVANTAGE

Fully auditable

The retrieved chunks are rendered in the UI, so you can inspect exactly which text reached the LLM — important for regulatory filings.

TRADE-OFF

No semantic matching

Keyword overlap misses paraphrased queries that true embedding similarity would catch.

TRADE-OFF

Context-window bound

The top_k cap keeps large filings from overflowing the LLM context window.

3

Upload state & timing

extraction is deferred on purpose
Upload -> _store_uploaded_files() snapshots BYTES only Analyze -> build_document_corpus() extract + chunk (once) _render_uploaded_docs_summary() shows ✓/⚠️ per file

Streamlit UploadedFile objects are recreated on every rerun and are not guaranteed to stay usable, so the bytes are snapshotted as {"name", "size", "bytes"}. Expensive PDF parsing then runs once, on the Analyze click — guarded by comparing an upload-set key so an unchanged set is never re-extracted. When the set does change, all previously built RAG artifacts are invalidated.

Scanned or image-only PDFs yield no text; they are reported per-file with a "⚠️ No extractable text" status rather than silently contributing nothing. Every stage prints to the terminal running streamlit run, so the pipeline is observable end-to-end.

Chroma persistence bridge

4 symbols
_build_save_record() session_state -> flat record dict ├─ _fundamental_commentary() 4 sections by canonical title ├─ recommendation verdict from parse_analysis, else overall_summary ├─ technology verdict + summary from tech_parsed └─ persona consensus block ONLY if its ticker matches the analysed one _save_current_analysis() lazy import + save + st.success(id)

_build_save_record returns (record, notes) — notes hold non-fatal warnings such as missing sections or a mismatched persona ticker, which are surfaced alongside the success message rather than silently dropped.

A persona result belonging to a different ticker is skipped, so a stale persona run can never be saved under another company's snapshot. The import of CHROMA_STORE is lazy so the app boot is unaffected, and the record shape matches exactly what that module renders.

crewAI persona bridge

3 symbols
run_persona_valuation(ticker, company) import PERSONA_AGENTS_CREW as pac # LAZY - crewAI is heavy res = pac.run_persona_crew(ticker, company or ticker) st.session_state.persona_result = res.model_dump() st.rerun() # render OUTSIDE the handler

The lazy import keeps crewAI out of the boot path and degrades gracefully with an install hint when it is missing. Storing the serialised model_dump() and calling st.rerun() means the long blocking crew run happens inside the handler while rendering happens on the next pass — so the persona section is independent of the standard pipeline and appears even for a persona-only run.

render_persona_valuation gates the rule-based comparison on deterministic_usable, so a degenerate rule-based range (where only one rule priced) hides the panel instead of advertising a point estimate as a range.

main()

the render pass
render_header() ticker, company, currency, analyze_btn, persona_btn, save_btn = render_sidebar() if analyze_btn and ticker and company: run_analysis(...) if persona_btn and ticker: run_persona_valuation(...) if save_btn: _save_current_analysis() if session_state.analysis_complete: render every result section if session_state.persona_result: render_persona_valuation(...) if neither: render the welcome screen

Streamlit re-executes the whole script on every interaction, so main() simply rebuilds the layout from cached session_state. The heavy work happens only inside the three button guards, and each of those ends in st.rerun() so rendering happens on a clean pass.
